# pstack in T3 Code

pstack skills are written for Cursor. In T3 Code (Claude or Codex threads),
read this file once per session, then map each Cursor name in a skill with the
tables below. `<pstack>` is the repository root, two folders above the real
path of this file (`readlink -f`). `<poteto-mode>` is the folder that holds
this file. Use absolute paths in every brief.

T3's tools are the `t3-code` MCP tools (`mcp__t3-code__<tool>` in Claude).
Some load late. In Claude, load one with `ToolSearch` (`select:<full name>`)
before its first call, and try a tool once before you decide it is missing.
When a step needs something with no row here and no T3 equivalent, put one
line in your reply, `Skipped in T3: <step>. <reason>.`, and go on to the next
step. Do not stop, ask, or retry.

## Starting agents

Every pstack spawn (a `Task` call, a `poteto-agent`, a panel seat, a swarm
worker, a judge) goes through `delegate_task`. The one exception is a quick
foreground helper on your own provider and model with no setting changes,
which may use the native subagent (`Agent` with `run_in_background: false` in
Claude, `spawn_agent` in Codex). Never start a background `Agent`.

| Cursor | T3 |
| --- | --- |
| `Task` | `delegate_task` |
| `model: <slug>` | `target: {providerInstanceId, model, options}` from the role's line in `~/.config/ferret-stack/models.md` (see Models). |
| `subagent_type: "poteto-agent"` | `delegate_task` with `role: "implementation"` (or the role that fits) and a `task` whose first two lines are `Read <poteto-mode>/worker.md before anything else.` and `Then read <poteto-mode>/SKILL.md in full, including its Principles index, and <poteto-mode>/t3.md.` |
| `subagent_type: "comment-sicko"` | `delegate_task` with `role: "review"` and a `task` whose first line is `Read <pstack>/agents/comment-sicko.md and act as it.` Then the files or diff to review. |
| `subagent_type: generalPurpose` | `delegate_task` with the worker.md line first, then the brief. |
| `run_in_background: true` | `mode: "async"`, the default. |
| `readonly: true` | `role: "review"` or `"research"`, and the brief says "Read-only: do not edit, commit, or push anything." After it finishes, check `git status` yourself. |
| `readonly: false` (agent mode) | The default. A child keeps T3's MCP tools. |
| `environment: "cloud"` | `isolation: "worktree"`. See Worktrees. |
| `environment: "local"` | `isolation: "shared"`, the default. |
| `cloud_base_branch: <b>` | `isolation: "worktree"`, and the brief's first step is `git fetch origin <b> && git checkout -B <b> origin/<b>`. |
| `resume` | A fresh `delegate_task` with the original brief, every later directive, and the earlier report pasted in. |
| `file_attachments` | List the absolute paths in the brief. |
| A Cursor Project worker | `delegate_task` with `isolation: "worktree"`. Use `t3_thread_launch` only when the user asks for a new thread. |
| Spawn N in one message | N `delegate_task` calls in one message, each with its own `clientRequestId` and `title`. |

Every call gets a `title` (what the child does), a `role`, and a unique
`clientRequestId`. Keep each returned `taskId`. Never put a secret in `task`.

## Waiting and results

- Do not poll a child. Its completion wakes your thread. While children run,
  do work that does not depend on them, and end your turn when none is left.
- A phase that needs every child (arena Phase C, swarm Phase C) starts on the
  wake of the last one. On each earlier wake, read that result, note it, and
  end the turn again.
- The wake carries the child's final report. For more, use `t3_thread_read` on
  its `childThreadId`. Name a child to the user by its `link`, verbatim.
- Stop a child you no longer need with `task_cancel`. A finished child keeps its
  result. Never use `t3_thread_interrupt` on a child.
- Each new review round is a new `delegate_task`, never `t3_thread_send`.

## Worktrees

- A worktree child starts from the parent's last commit. Uncommitted edits stay
  out. When a brief needs them, such as interrogate's scope, write them first
  with `git add -N . && git diff HEAD > <scratch>/scope.patch`, and make
  `git apply <scratch>/scope.patch` the brief's first step.
- Each worktree child commits its work on its own branch and reports the
  absolute worktree path, the branch, and the commit SHA. Read candidates from
  there, or with `git diff <base>..<branch>` from your checkout.
- T3 keeps worktrees under `~/.t3/worktrees/<project>/`. Cursor's
  `~/.cursor/worktrees/` means that folder.

## Models

`/setup-pstack` writes `~/.config/ferret-stack/models.md`. Read it before the
first spawn of a session. Each line is `role: value`, and a value is one target
or a comma-separated list of targets:

```
<providerInstanceId>/<model id> <option id>=<value>
claudeAgent/claude-opus-5-5 effort=xhigh
codex/gpt-6-luna reasoningEffort=high
antigravity/gemini-4-neon thought_level=xhigh
inherit-parent
```

A target becomes `target: {providerInstanceId, model, options: {<option id>: <value>}}`.
`inherit-parent` or `auto` means: omit `target`, so the child runs on your
model. A role with no line, or no file, uses the default slug in the skill,
mapped with this table:

| Cursor slug | T3 target |
| --- | --- |
| `claude-opus-5-5-<effort>[-fast]` | `claudeAgent/claude-opus-5-5 effort=<effort>`. Drop `-fast`. Fast mode stays off unless the user asks for it. |
| `claude-fable-5-2-<effort>` | `claudeAgent/claude-fable-5-2 effort=<effort>` |
| `claude-sonnet-5-5-<effort>` | `claudeAgent/claude-sonnet-5-5 effort=<effort>` |
| `gemini-4-neon-<effort>` | `antigravity/gemini-4-neon thought_level=<effort>` |
| `gpt-*-<effort>` | `codex/<model> reasoningEffort=<effort>` |

Option names differ by provider: Claude uses `effort`, Codex
`reasoningEffort`, and Antigravity `thought_level`. Check them, and which
providers are enabled, with `orchestrator_capabilities` once per thread before
the first `delegate_task`. No role runs above `xhigh`.

When a target's provider is disabled or its model is missing, use the closest
model of the same family that `orchestrator_capabilities` lists, then the
skill's fallback, then drop the seat. Say which. A panel keeps at least two
seats from different vendors.

**Vendor** comes from the model id, not the provider: `claude-*` (Fable
included) is Anthropic, `gpt-*` is OpenAI, `gemini-*` is Google, and `grok-*`
is xAI. Antigravity can also run Claude models, and those still count as
Anthropic.

## Other Cursor names

| Cursor | T3 |
| --- | --- |
| Open a todolist, or copy steps into the todolist tool | `TodoWrite` in Claude or `update_plan` in Codex, when the session has it. T3 threads often do not. Then keep the list in your reply, numbered, and restate it with marks at each phase. |
| `AskQuestion` | `AskUserQuestion` in Claude. Otherwise ask in plain text. A child never asks. It decides and reports, per worker.md. |
| `/loop` | In Claude Code, its built-in `/loop`. Otherwise `schedule_task` with `{type: "interval", everyMs}` and `bindToCurrentThread: true`. Never sleep or poll in a loop. |
| Cursor Automations, routines, webhooks, `SendToUser` | `schedule_task` (fixed time, interval, or `{type: "webhook"}`). Secrets go through `request_secret`. |
| `.cursor/rules/*.mdc`, always-applied rules | `CLAUDE.md` in Claude, `AGENTS.md` in Codex. The models rule is the exception. See Models. |
| `~/.cursor/skills/`, `.cursor/skills/` | User skills: `~/.claude/skills/` and `~/.codex/skills/`. Project skills: `.claude/skills/<name>/`, plus a symlink at `.agents/skills/<name>` for Codex. |
| `~/.cursor/plugins/` | pstack's skills are linked into `~/.claude/skills/` and `~/.codex/skills/`. `<pstack>` is the repo they link to. |
| Agent transcripts (`~/.cursor/projects/<slug>/agent-transcripts/`) | T3 threads: `t3_thread_search`, then `t3_thread_read`. Raw files: Claude Code at `~/.claude/projects/<slug>/*.jsonl` (the slug is the path with `/` and `.` turned into `-`), and Codex at `~/.codex/sessions/<yyyy>/<mm>/<dd>/*.jsonl`. Read only the workspace's own history. |
| Cursor's built-in PR tool | `gh`. After you create or push to a PR, call `link_pull_request` with its URL. |
| Waiting on PR checks or reviews (`watch-pr` in `drive` mode) | `watch_pull_request`, then end your turn. T3 wakes you on failed checks, new comments, or conflicts. Do not call it again on a wake. `watch-pr` needs `bun`, which may be missing. For a one-shot status, `gh pr view <pr> --json statusCheckRollup,reviewDecision,mergeable` and `gh pr checks <pr>` work too. Call `unwatch_pull_request` before you hand back. |
| Bugbot | Bugbot comments are ordinary review threads, so triage them per `references/bugbot-triage.md`. Skip a step that starts or waits for Bugbot when the PR has no Bugbot check. |
| `control-ui` (browser, Electron, web) | T3's `preview_open`, `preview_snapshot`, `preview_act`, and `preview_wait_for`, or Playwright. Close any tab you opened before you reply. |
| `control-cli` (CLIs, TUIs) | Run it in the shell, or in `tmux` for an interactive TUI, and read the output. |
| Simulators and devices | T3's `device_open`, `device_screenshot`, and `device_close`. |
| `/deslop` (cursor-team-kit, not installed) | `Skipped in T3: deslop. Not installed.` Then run **no-comments** if the step was about comments. |
| Cursor cloud agents' dashboard or machine | Skip with the line. |
| Showing a chart, diagram, or visual summary | `html_preview`, then `html_render` with the returned height. A picture the user wants to keep is a `.png` file and its path. |
